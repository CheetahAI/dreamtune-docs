## Before you connect

Create a Dreamtune workspace API key with only the permissions you need.
Hosted HTTP setup needs no Dreamtune package installation. Local stdio setup
requires Node.js 22.20 or later and the published CLI.

## Configure

Merge this server entry into your private Zed settings. Preserve any other servers or settings.

```json
{
  "context_servers": {
    "dreamtune": {
      "url": "https://mcp.dreamtunelabs.com/mcp",
      "headers": {
        "X-Dreamtune-API-Key": "YOUR_DREAMTUNE_KEY"
      }
    }
  }
}
```

Replace the key in private settings. Zed uses context_servers rather than mcpServers. Open the Agent Panel's MCP controls to inspect availability; do not assume another editor's environment-variable interpolation works in Zed.

## Verify the connection

Restart the client after changing settings or its environment. Open its MCP
server/tool status view and check that Dreamtune tools are listed. Ask it:

> Use Dreamtune to read model request limits. Do not execute a model, tool or GPU.

Confirm model_limits returns limits before authorizing paid work. Then inspect a
catalog schema and use one explicitly approved operation. Keep client approval
controls enabled. Never put the key in a chat message, URL or repository.

## Add workflow instructions

Install the [Dreamtune skills](/connect/skills-install) into the skills directory
supported by your client, or copy the platform skill into a user instruction
workflow. A skill guides the agent; MCP provides execution. Neither grants extra
key permissions. See [troubleshooting](/errors) for 401, missing scopes, timeouts
and key/environment problems.

Configuration verified against [the official client documentation](https://zed.dev/docs/ai/mcp).
